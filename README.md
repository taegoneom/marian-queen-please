# 마리안 : 퀸이 갖고 싶어요

Windows 터미널에서 무료 양자 난수로 10명씩 관측하고, 출격 신호와 모집 결과를 기록하는 개인용 유틸리티입니다. Python 3.10 이상이 필요하며 추가 패키지는 없습니다.

모집 재화는 아끼고, 뽑을 타이밍은 조금 더 재미있게 정해 보자는 발상에서 만든 오락용 도구입니다. 양자 난수로 생성한 관측 기록과 게임 서버의 모집은 서로 독립적인 확률 과정이며, 이 도구는 실제 당첨 확률을 높이거나 결과를 예측하지 않습니다.

1. `main.py` 상단의 `COMMANDER_NAME = "여기에지휘관닉네임을입력해주세요"`를 본인 닉네임으로 바꾸세요. 그대로 실행하면 처음에 이름을 입력받습니다.
2. `start.bat`을 실행하세요. 또는 `python main.py --auto`.
3. **A** 일시정지 → **C** 설정 변경. **Q** 종료.

시작할 때 **‘무슨 픽업이에요?’**에서 `1. 마리안 : 퀸` 또는 `2. 홍련 : 신살`을 번호로 선택하세요. Enter는 지난 선택을 유지합니다. 실행 중에는 **A → C → 픽업 종류**에서 번호로 바꿀 수 있습니다. 관측 명단·픽업 이름·알림·게임 결과·통계는 선택한 모집을 따릅니다. 미등장 횟수와 첫 알림 연습 여부도 픽업별로 구분하며, 기존 기록은 마리안 모집으로 보존합니다. 골드 마일리지 잔액은 함께 사용합니다. 필그림 선택 모집은 지원하지 않습니다.

시작할 때 예정한 게임 10연차 횟수를 입력하면 0개·1개 이상·2개 이상·3개 이상의 확률을 보여 줍니다. 입력한 횟수를 알림 기준으로 사용하려면 이어지는 질문에 `Y`를 입력하세요. Enter를 누르면 기존 알림 기준을 유지합니다. `0`은 계획 미정입니다. 시작 질문은 C의 `ask_plan_on_start`를 false로 바꾸면 생략할 수 있습니다.

기본값: 10명마다 1.000000~1.100000초 준비, LfD/Quantis 무료 QRNG, API 요청 간격 최소 1.1초, 선택한 픽업 연속 미등장 누적 기준 **99% 초과(1회 기준 460회 = 10연차 46번)**, 첫 신호 연습, 게임 입력 제한 30초입니다. 출격 신호는 경고음 두 번으로 알립니다. 준비 시간은 1마이크로초 단위로 무작위 선택하며 API 응답 시간은 별도로 추가됩니다.

**API 이용 안내:** 코드를 내려받은 뒤 요청 간격이나 호출 제한을 변경해 API를 과도하게 호출하면, 제공자의 요청 제한(레이트 리밋)이나 접근 차단이 발생할 수 있습니다. 이러한 변경으로 발생한 이용 제한 및 서비스 중단에 대해서는 이 저장소의 제공자가 책임지지 않으므로, 제공자의 이용 정책을 확인하고 기본 호출 제한을 유지해 주세요.

최소 1.1초 간격은 **이 프로그램 자체의 보호 설정**입니다. 2026-10-30 확인 기준 [LfD 공식 API 문서](https://www.lfdr.de/QRNG/)에는 초당·분당 허용 요청 수나 일일 한도가 명시돼 있지 않으므로, 1.1초 간격이 제공자가 보장한 허용 범위이거나 차단을 방지하는 기준이라고 단정할 수 없습니다.

**준비 시간 변경:** 현재 기본은 1~1.1초입니다. **A**로 멈춘 뒤 **C**에서 최소·최대 시간을 변경할 수 있습니다. 최소 시간은 최대 시간 이하여야 합니다. 파일로 수정하려면 프로그램을 종료하고 `config.json`의 아래 항목을 변경한 뒤 다시 실행하세요. 아직 `config.json`이 없다면 `config.example.json`을 수정하면 됩니다.

```json
{
  "randomize_animation": true,
  "animation_min_seconds": 1,
  "animation_max_seconds": 1.1,
  "qrng_min_request_interval_seconds": 1.1
}
```

위 값은 전체 설정 중 변경할 항목만 보여 줍니다. 나머지 항목은 유지하세요. 자동 10연차마다 API 응답 한 번을 사용하며, 준비 시간을 줄여도 요청 시작 시각 사이에는 최소 1.1초를 둡니다. 기존 설정이 1~1.1초 미만이면 불러올 때 1.1초로 보정합니다. 이 제한은 유지하고 제공자의 이용 정책을 우선해 주세요. HTTP 403·429가 발생하면 자동 재시도 없이 중지합니다.

**알림 대기시간:** 알림은 선택한 픽업이 460회 연속 미등장해야 발생하며, 중간에 선택한 픽업이 관측되면 횟수가 초기화됩니다. 기본 설정 그대로 켜 두거나 준비 시간을 줄이더라도, 정해진 시간 안에 알림이 온다는 보장이나 유한한 최대 대기시간은 없습니다. 오랫동안 알림이 없을 수 있고, 첫 알림은 연습으로 넘기므로 실제 사용할 두 번째 알림까지는 더 기다릴 수 있습니다.

매회 픽업 1%일 때, **처음부터 정한 모집 구간**의 확률은 다음과 같습니다. 10연차 12번은 120회, 20번은 200회, 46번은 460회입니다. ‘2개 이상’과 ‘3개 이상’은 누적 사건이므로 각 열을 더하면 안 됩니다.

| 모집 횟수 | 0개 | 1개 이상 | 2개 이상 | 3개 이상 |
|---|---:|---:|---:|---:|
| 120회 | 29.938039% | 70.061961% | 33.773429% | 11.963654% |
| 200회 | 13.397967% | 86.602033% | 59.535432% | 32.332131% |
| 460회 | 0.982176% | 99.017824% | 94.454175% | 83.874809% |

**시간 참고(기본 460회 기준):** 첫 46묶음이 모두 미등장해 가장 이른 기회에 알림이 발생할 확률은 **0.982176%**입니다. 이때 준비 시간 합계는 **46~50.6초**이고 API 응답·저장·화면 출력 시간이 추가됩니다. 반복 중 초기화되는 경우까지 포함하면 대기시간은 길어집니다.

| 첫 알림까지 걸리는 시간 | 이보다 오래 걸릴 확률(준비 시간만 계산) |
|---|---:|
| 5분 | 약 78.3% |
| 10분 | 약 59.1% |
| 20분 | 약 33.7% |
| 30분 | 약 19.2% |
| 60분 | 약 3.6% |

위 표는 **0회에서 시작해 첫 알림을 기다리는 경우**, API 지연 없이 묶음마다 1~1.1초의 균등 대기시간을 사용하는 이론 참고치입니다. 10연차 무당첨 확률 `a = 0.99^10`으로 46연속 무당첨 묶음을 기다리는 상태 전이로 계산했습니다. 5분 수치는 대기시간 합의 분포까지 계산했고, 나머지는 평균 주기에 따른 근사입니다. 이 조건의 평균 대기는 약 **18분 27초**입니다. 실제 실행에는 API 응답 시간이 추가되므로 더 길어질 수 있고, 게임 입력·일시정지·첫 알림 연습 처리 시간도 별도입니다. 계획 횟수나 목표를 변경하면 이 참고 표는 적용되지 않습니다. [연속 사건 대기시간 연구](https://arxiv.org/abs/2210.08797)

신호에서 **D** 뽑았어요 / **N** 안 뽑았어요. 결과는 `픽업 기타SSR 나머지` 순서로 `0 0 10`, `1 0 9`처럼 입력하세요. SR/R을 구분하면 `픽업 기타SSR SR R` 네 숫자입니다.

**게임 결과와 시간 연결:** 첫 결과뿐 아니라 결과 입력을 마칠 때마다, 저장 시각(KST)을 기준으로 연속 미등장 카운트를 0으로 초기화하고 새 관측 구간을 시작합니다. 전체 기록과 마일리지는 유지하며 입력 중에는 관측을 멈춥니다. 자동 관측 중 `R`로 기록해도 입력 후 자동으로 이어집니다. 다시 시작해도 API 요청 간격은 유지됩니다. 입력된 결과를 당첨 가중치나 난수 시드로 쓰지는 않습니다.

화면에는 게임 기록의 픽업 비율·표기 1%와의 차이·Wilson 95% 구간을 표시합니다. 다음 10회에서 1개 이상 얻을 이론 확률은 **9.561792%**이며, 계획 횟수가 있으면 이번 실행에서 기록한 횟수를 빼고 남은 모집의 확률도 갱신합니다. 실측 비율은 기록 요약이며 다음 결과의 예측치는 아닙니다. 시간 기준을 새로 잡아도 매회 표기 확률 1%는 유지됩니다.

설정은 `config.example.json`에서 시작해 `config.json`에 저장됩니다. 기존 골드 마일리지는 **M**에서 입력하세요. 기록은 `runtime/`에 저장되고 Git에는 포함하지 않습니다. 누적 기준은 다음 게임 모집의 당첨률을 뜻하지 않습니다.

대시보드에는 선택한 픽업·기타 SSR·SR·R의 **전체 누적 수량과 실측 비율**, **이번 실행의 수량과 실측 비율**을 함께 표시합니다. 재시작해도 전체 기록은 유지됩니다. 골드 마일리지는 직접 기록한 게임 모집 중 유료 모집 1회당 1장씩 반영하며, 유료 10회 기록은 +10장, 무료 모집은 +0장입니다. 화면의 자동 관측 횟수만으로 마일리지가 늘어나지는 않습니다.

각 등급의 실측 비율 옆에는 기준보다 높은지·낮은지와 차이(%p)를 표시합니다. 이는 높고 낮음을 설명하는 수치이며, 적은 표본만으로 성능을 판정하는 검정은 아닙니다. 콘솔에는 실행 경과시간과 시간 참고치도 표시하고 Windows의 `cls`로 화면을 갱신합니다.
